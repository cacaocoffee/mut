## 01-A · 탐색

**목적** — 4개 축을 교차해 후보를 좁힌다. 이 화면의 성패는 **필터를 걸었을 때 빈 결과가
나오지 않는 것**이다.

**진입** — 홈 · 나브 탭 · 카테고리 페이지의 "더 좁히기" · 외부 검색(필터 없는 상태)

### 레이아웃

```
.page-head    Multi-dimensional search
              칵테일 탐색   Browse 24 of 24 entries      [리드문]
──────────────────────────────── 2px ───────────────────────────
┌ .filter-panel (296px, sticky) ┬ 결과 ──────────────────────┐
│  필터 FILTERS      초기화      │  24  개 결과 · 요약        │
│  ─────────── 2px ───────────  │  ──────────── 2px ─────── │
│  당도 SWEETNESS               │  ┌─────┐ ┌─────┐ ┌─────┐  │
│    [전체 ] [드라이] …          │  │카드 │ │카드 │ │카드 │  │
│  기주 BASE SPIRIT   복수 선택  │  └─────┘ └─────┘ └─────┘  │
│    (칩 + 개수)                │                            │
│  스타일 STYLE      복수 선택   │                            │
│  맛/향 FLAVOR PROFILE         │                            │
│  도수 ABV          복수 선택   │                            │
│  검색 KEYWORD                 │                            │
└───────────────────────────────┴────────────────────────────┘
```

### 필터 패널

| 축 | 컨트롤 | 결합 | 근거 |
|---|---|---|---|
| 당도 | 세로 세그먼트 5칸 (전체 + 4단계) | 단일 | `FR-COCKTAIL-007` |
| 기주 | 칩 | **OR** | `FR-SEARCH-001` |
| 스타일 | 칩 | **OR** | 〃 |
| 맛 / 향 | 태그 칩 | **AND** | 〃 |
| 도수 | 칩 4구간 | **OR** | `FR-SEARCH-003` |
| 키워드 | 텍스트 | AND | `FR-SEARCH-006` |

> **맛·향만 AND인 것이 의도다.** "시트러스 **그리고** 허브"를 원하지 "또는"이 아니다.
> 나머지 축은 "진 **또는** 보드카"가 자연스럽다.

#### 결과 개수 — 이 화면의 핵심

**모든 필터 값 옆에 숫자가 붙고, 0건이면 비활성화된다** (`FR-SEARCH-002`).
PRD가 "초기부터 넣지 않으면 나중에 UI를 다시 짜야 한다"고 못박은 지점이다.

```
기주 BASE SPIRIT                복수 선택
[진 5] [보드카 4] [위스키 5] [럼 4] [데킬라·메즈칼 2] [전통주 3] [무알콜 1]
```

동작 확인 — 기주를 `위스키`로 좁히면 도수 카운트가 `논알콜 0 · 저 0 · 중 1 · 고 4`가 되어
**논알콜·저도수 칩이 자동 비활성화**된다. 연속 슬라이더로는 만들 수 없던 동작이고,
도수를 4구간 칩으로 바꾼 이유다 ([ADR-0003](../decisions/ADR-0003-graph-source-and-abv-bands.md)).

| 규칙 | |
|---|---|
| 0건 값 | `disabled` + `opacity .32`. **숨기지 않는다** — 왜 못 고르는지 보여야 한다 |
| 이미 선택된 값 | 0이어도 비활성화하지 않는다. 해제할 수 있어야 한다 |
| 코퍼스에 0건인 값 | **아예 렌더하지 않는다** (`floral` 등). 조합 0건과 다르다 |

#### URL

필터 상태는 쿼리스트링에 실린다 (`FR-SEARCH-005`).

```
/?sweet=1&base=위스키&style=sour&flavor=citrus,herbal&abv=high&q=사워
```

- 뒤로 가기로 이전 필터 상태로 돌아간다
- 공유하면 같은 결과가 열린다
- **`noindex`** — 색인은 카테고리 경로만 받는다

### 결과 영역

**정렬은 도수 낮은 순 고정이다.** 정렬 선택지를 주지 않는다 —
필터 축이 이미 여섯이라 정렬까지 열면 조작 지점이 너무 많아진다.

#### 카드

```
┌──────────────┐
│  IMAGE 4:5   │   해칭 자리표시자 + 영문명
├──────────────┤
│ 네그로니   24 │   ko 19px/800 · abv 20px/800
│ NEGRONI  %ABV │   en 11px uppercase
│ [진] [드라이]  │   기주 · 당도 태그
│ BITTER HERBAL │   향 태그 최대 3
│ Stir·올드패션드  상세→ │
└──────────────┘
```

카드 전체가 링크다. 호버 시 테두리가 accent로 바뀐다.

### 상태

| 상태 | 표현 |
|---|---|
| 빈 결과 | `조건에 맞는 항목이 없습니다` / `도수 구간을 넓히거나 맛/향 태그를 줄여보세요.` |
| 로딩 | 카드 스켈레톤 9개 |
| 에러 | 목록 영역만 교체. 필터 패널은 살려둔다 |

### 현재 구현과의 차이

| 항목 | 상태 |
|---|---|
| 필터 6축 · 패싯 카운트 · URL 동기화 | ✅ |
| 초성 · 별칭 검색 | ⬜ 지금은 `String.includes` 단순 매칭 |
| 서버 패싯 (`GET /cocktails/facets`) | ⬜ 클라이언트 계산. **UI 계약은 동일** |

**목적** — SEO 경쟁력이 여기서 갈린다. PRD가 "가장 많은 시간을 쓴다"고 한 화면이다.

**진입** — 탐색 카드 · 카테고리 · 검색 · **바 상세의 시그니처** ★ · 외부 검색

### 블록별 규칙

| 블록 | 규칙 | 근거 |
|---|---|---|
| 스펙 스트립 | 5칸 — ABV · STYLE · GLASSWARE · TECHNIQUE · SWEETNESS. 모바일 2열 | `FR-COCKTAIL-017` |
| 분류 3축 | **각각 카테고리 페이지로 링크** | `FR-COCKTAIL-018` |
| 잔 수 | 1~8. 고정 표기(`1조각`·`2 dash`)는 **배수에서 제외** | `FR-COCKTAIL-019` |
| 단위 | `ml` / `oz` 토글. `dash`·`barspoon`·`piece`는 변환하지 않는다 | `FR-COCKTAIL-020` |
| 대체재 | `대체 가능 ⓘ` 클릭 시 accent 틴트 박스로 펼침. 한 번에 하나만 | `FR-COCKTAIL-021` |
| 제조 순서 | 2자리 번호(`01`) accent 26px + 본문. 각 행 하단 1px 규칙선 | `FR-COCKTAIL-017` |
| 맛 프로필 | 레이더 + **막대 5행 병기**. 차트만 두면 스크린리더가 읽을 수 없다 | 접근성 |
| 배리에이션 | **`style_primary` 1순위 · 기주 2순위** | `FR-COCKTAIL-024` |
| **마실 수 있는 바** ★ | 시그니처·상시 메뉴 등록 바. 파트너 부스팅 **상위 3중 1까지** | `FR-COCKTAIL-025` |
| Schema.org | `Recipe` JSON-LD | `FR-COCKTAIL-026` |
| 국내 구매 가이드 | 재료별 유통 여부 · 대체재 · 가격대 | PRD 6.1 |


## 01-C · 카테고리

**목적** — SEO 랜딩. 검색 유입의 절반이 여기로 들어온다.

**경로** — `/cocktails/base/{slug}` · `/cocktails/style/{slug}` · `/cocktails/method/{slug}`

> **단일 축 경로만 만든다** (`FR-COCKTAIL-029`).
> 축 조합 경로(`/cocktails/base/gin/style/sour/`)는 **만들지 않는다** (`FR-COCKTAIL-030`).
> 조합은 쿼리스트링 필터로만 표현한다.

### 레이아웃

탐색 화면과 같은 카드 그리드를 쓰되 **필터 패널이 없다.**

```
.page-head   Category · Base spirit
             진 GIN            5 entries
             ───────── 2px ─────────
             [고유 소개 문구 2~3문단]      ← 색인 가치
             ───────── 2px ─────────
             카드 그리드
             [더 좁히기 → /?base=gin]
```

| 규칙 | |
|---|---|
| 소개 문구 | **카테고리마다 고유해야 한다** (`FR-COCKTAIL-031`). 목록만 있는 페이지는 색인 가치가 없다 |
| 더 좁히기 | 탐색 화면으로, 해당 축이 선택된 상태로 이동 |
| 정렬 | 도수 낮은 순 (탐색과 동일) |
| 색인 | ✅ — `noindex`를 붙이지 않는다 |

메이킹 방법 카테고리는 **난이도 프록시**로 소개한다 — `빌드`는 "잔과 바 스푼만 있으면
오늘 만들 수 있는 것"으로 설명한다 (PRD 5.3).

### 상태

항목 0건인 카테고리(`브랜디`·`리큐르`·`와인`)는 **경로를 생성하지 않는다.**
enum에는 있지만 페이지는 만들지 않는다 — 빈 랜딩은 SEO에 해롭다.

## 01-D · 재료 사전

### 상세 구성

| **국내 유통** | `흔함` · `전문점` · `직구만` · `국내 미유통` | `PRIN-P05` |

| **이 재료를 쓰는 칵테일** | 카드 그리드 | `FR-INGREDIENT-002` |

### 광고성 구분

브랜드를 언급할 때 **광고성 여부를 시각적으로 구분한다** (`FR-INGREDIENT-004`).

```
대표 브랜드
  탱커레이            일반 표기
  봄베이 사파이어  [제휴]   ← is_sponsored
```

`제휴` 라벨은 파트너 배지와 **다른 색**을 쓴다 (`FR-PARTNER-006`).
