> **Phase 1a의 유일한 병목이다.** 에디터가 발행할 화면이 없으면 칵테일 100종을 넣을 수 없다.

---

## 0. 이 화면의 사용자

**하루 3~5종을 쓰는 에디터 한 명.** PRD 15장이 "M3까지 도달 가능"의 근거로 잡은 페이스다.

설계 기준이 여기서 나온다.

| | |
|---|---|
| **속도가 품질보다 먼저다** | 한 칵테일을 20분 안에 끝낼 수 있어야 100종이 나온다 |
| **개발자를 부르지 않는다** | 어떤 작업도 SQL이나 배포를 요구하지 않는다 (`FR-ADMIN-001`) |
| **막힌 이유가 즉시 보인다** | 발행 버튼을 눌러서야 알게 되면 왕복이 생긴다 |

공개 화면과 **같은 디자인 시스템**을 쓴다 ([SPEC-05 §1](../spec/SPEC-05_아키텍처.md)).
별도 앱을 만들지 않는다 — 인증과 토큰을 공유하고, 두 벌을 유지하지 않는다.

밀도는 더 높다. 어드민은 표가 주인공이고 여백이 아니다.

| 화면 | 경로 | 권한 |
|---|---|---|
| [06-A 할 일](#06-a--할-일) | `/admin` | 🔒 `editor` |
| [06-B 칵테일 목록](#06-b--칵테일-목록) | `/admin/cocktails` | 🔒 `editor` |
| [06-C 칵테일 편집](#06-c--칵테일-편집) ★ | `/admin/cocktails/{id}` | 🔒 `editor` |
| [06-D 재료 마스터](#06-d--재료-마스터) | `/admin/ingredients` | 🔒 `editor` / 승인은 `admin` |
| [06-E 감사 로그](#06-e--감사-로그) | `/admin/audit-logs` | 🔒 `admin` |

전 화면 CSR. 정적 생성하지 않는다.

## 06-A · 할 일

에디터가 로그인해서 **처음 보는 화면.** "오늘 뭘 해야 하나"에 답한다.

```
.page-head   Admin
             할 일        에디터 이름
─────────────────────── 2px ───────────────────────
┌ 발행 대기 ──────────┬ 검증 필요 ────────────────┐
│  draft 12건         │  영업시간 90일 경과  3건   │  ← 1b
│  ├ 네그로니  남은 2 │  재료 승인 대기      2건   │
│  ├ 김렛      남은 1 │                           │
│  └ …                │                           │
├─────────────────────┴───────────────────────────┤
│ 최근 발행                                        │
│  네그로니  2026-08-06 14:20  나                  │
└─────────────────────────────────────────────────┘
```

| 블록 | 규칙 | 근거 |
|---|---|---|
| 발행 대기 | **`남은 N`이 게이트 미충족 개수.** 0이면 바로 발행 가능 | `FR-COCKTAIL-010` |
| 검증 필요 | `hours_verified_at` 만료 · 재료 승인 대기 | `FR-ADMIN-004` |
| 최근 발행 | `audit_log` 최근 10건 | `FR-ADMIN-005` |

`남은 N`을 목록에 띄우는 게 핵심이다. **어떤 초안이 발행에 가까운지가 한눈에 보여야**
에디터가 마무리부터 한다.

### 발행 조건 패널 — 이 화면의 핵심

**게이트를 발행 버튼 뒤에 숨기지 않는다.** 편집 내내 우측에 붙어 실시간으로 갱신된다.

`FR-ADMIN-003`은 "실패 항목을 전부 한 번에 보여준다"고 요구하지만,
**더 나은 건 애초에 누르기 전부터 보이는 것**이다. 왕복이 사라진다.

| 항목 | 표시 | 게이트 |
|---|---|---|
| 분류 3축 | 셋 다 채워졌나 | `GATE-COCKTAIL-02` |
| 표준 레시피 | 재료 1개+ · 스텝 1개+ | `GATE-COCKTAIL-03` |
| 재료 마스터 참조 | 전부 참조인가 | `GATE-COCKTAIL-04` |
| **향과 맛 서술** | 비었나 | `GATE-COCKTAIL-01` |
| 클래식 story | `is_classic`일 때만 | `GATE-COCKTAIL-05` |
| 미유통 대체재 | **어떤 재료가 걸렸는지까지** | `GATE-COCKTAIL-06` |

미충족 항목은 **무엇이 걸렸는지 이름을 댄다.** "대체재 필요"가 아니라
"대체재 필요 → 오르자 시럽"이라고 쓴다. 클릭하면 해당 입력란으로 스크롤한다.

발행 버튼은 남은 게 있으면 `disabled`. 눌러도 실패할 것을 누르게 하지 않는다.

> 클라이언트 판정은 **UX 편의**다. 서버가 다시 검사하고, 서버 판정이 최종이다
> (`PRIN-T05`). 클라이언트가 통과시켰는데 서버가 막으면 `violations[]`를 같은 패널에 표시한다.

### 입력 강제

| 필드 | 규칙 | 근거 |
|---|---|---|
| 분류 3축 | **비우면 저장 자체가 안 된다.** 발행이 아니라 저장이다 | `FR-COCKTAIL-001` |
| `style_primary` | `styles` 선택 결과에서만 고를 수 있다. 드롭다운이 그것만 담는다 | `FR-COCKTAIL-002` |
| 향·맛 태그 | **4개째는 선택이 막힌다.** 지우고 고르라고 안내 | `FR-COCKTAIL-008` |
| 재료 | **프리텍스트 입력란이 없다.** 마스터 검색 → 선택만 | `FR-COCKTAIL-004` |
| `slug` | 이름에서 자동 생성. **발행 후 잠금(🔒)** | `FR-COCKTAIL-014` |
| 도수 | 자동 계산값 표시 + `수동` 체크 시 덮어쓰기 | `FR-COCKTAIL-006` |

**재료에 프리텍스트 입력란이 없는 것이 `PRIN-D01`의 UI 구현이다.**
있으면 급할 때 반드시 쓰이고, 그 순간 역검색과 바 연결이 깨진다.

마스터에 없는 재료는 그 자리에서 **신규 요청**을 만든다 → 승인 대기 상태로 들어가고
(`FR-ADMIN-007`), 승인 전에는 발행 게이트가 막는다.

### 재료 행

```
재료               용량   단위    역할       대체재        술장
진 (Dry Gin)       30     ml ▾   base ▾    —            ☑
캄파리 (Campari)   30     ml ▾   modifier  아페롤 ▾      ☑
오렌지 필          —      piece  garnish   —            ☐  ← 자동 해제
```

- `garnish` 역할을 고르면 `counts_for_stock`이 자동으로 꺼진다 (`R-F2.2-5`)
- 대체재를 고르면 설명 입력란이 딸려 나온다. **비우면 저장은 되지만 게이트가 잡는다**
- 도수는 재료를 바꿀 때마다 재계산된다

### 상태

| 상태 | 표현 |
|---|---|
| 저장 중 | 우측 패널에 `저장 중` — 편집을 막지 않는다 |
| 저장 실패 | 상단 배너 + 재시도. **입력값을 날리지 않는다** |
| 발행 성공 | 상태가 `published`로, `slug` 잠금, 공개 페이지 링크 노출 |
| 발행 실패(서버) | `violations[]`를 발행 조건 패널에 병합 |
| 동시 편집 충돌 | `409` → "다른 사람이 먼저 저장했습니다" + 차이 표시 |

## 06-B · 칵테일 목록

```
칵테일  128건        [상태 ▾] [기주 ▾] [검색]      [＋ 새 칵테일]
────────────────────────────── 2px ──────────────────────────────
이름         상태      3축              향·맛   남은   수정
네그로니     published  진·spirit·Stir   3       —     08-06
김렛         draft      진·sour·Shake    2       1     08-05
마르가리타   draft      —                0       4     08-04   ← 3축 비어있음
```

| 규칙 | |
|---|---|
| `남은` | 게이트 미충족 개수. 정렬 가능 — **발행에 가까운 순으로 볼 수 있다** |
| 3축 | 비면 빨간 `—`. 목록에서 바로 보인다 |
| 기본 정렬 | 수정일 역순 |
| 필터 | 상태 · 기주 · 검색 |

목록에 `남은`을 두는 이유는 **마무리 우선 작업**을 가능하게 하기 위해서다.
초안 12개 중 1개만 남은 것부터 끝내는 게 100종에 가장 빨리 닿는 길이다.

## 06-D · 재료 마스터

**국내 유통 기준 200~300개 상한.** 무한정 늘리면 역검색 UX가 무너진다 (`FR-INGREDIENT-001`).

```
재료  214 / 300        [카테고리 ▾] [유통 ▾] [승인대기 2]
──────────────────────────── 2px ────────────────────────────
이름          카테고리   도수   국내 유통    대체재   사용   상태
진            spirit     40    흔함         —        12    승인
오르자 시럽    syrup      0     직구만       ⚠ 없음   1     승인
```

| 규칙 | 근거 |
|---|---|
| 상한 근접 시 경고 | `214 / 300` — 280 넘으면 accent |
| `직구만`·`미유통`인데 대체재 없으면 **⚠** | `INV-INGREDIENT-01` |
| `사용` = 이 재료를 쓰는 칵테일 수 | 0이면 삭제 후보 |
| 신규 추가는 **승인 대기** | `FR-ADMIN-007` — 승인은 `admin` |

브랜드 등록 시 **`제휴` 여부를 반드시 고른다** (`FR-INGREDIENT-004`).
기본값은 `일반`이고, 켜면 공개 화면에 라벨이 붙는다.

## 06-E · 감사 로그

```
감사 로그         [대상 ▾] [작업 ▾] [기간]
────────────────────────── 2px ──────────────────────────
일시               작업        대상          수행자   변경
08-06 14:20       publish     네그로니       나       draft→published
08-06 11:02       tier_change 바 참          관리자   listed→verified
```

`PRIN-T08`의 4종을 전부 받는다 — 발행 상태 전이 · 제휴 등급 변경 ·
큐레이션 순위 변경 · 바 정보 검증.

**되돌리기 버튼을 두지 않는다.** 로그는 기록이지 조작 도구가 아니다.
되돌리려면 정상 경로로 다시 작업하고, 그것도 로그에 남는다.

## 이 화면에 **없는** 것

| 없는 것 | 왜 |
|---|---|
| **노출 규칙 조정** (부스팅 한도 · 홈 슬롯 비율) | `PRIN-P02` · `FR-ADMIN-006`. 입력란을 만드는 순간 조정된다. 코드를 고치고 배포해야 바뀐다 |
| 별점 · 평점 입력 | `INV-BAR-01` |
| 재료 프리텍스트 입력 | `PRIN-D01` |
| 물리 삭제 | `PRIN-D05` — 보관(`archived`)만 있다 |
| 제휴 등급 변경 (`editor`) | `admin` 전용. **권한 분리가 중립성 장치다** ([SPEC-08 §2.2](../spec/SPEC-08_보안_권한_개인정보.md)) |
| 감사 로그 되돌리기 | 위 |

**"없는 것" 목록이 이 화면 명세의 절반이다.** 어드민은 할 수 있는 일보다
**할 수 없게 만든 일**이 제품을 지킨다.
