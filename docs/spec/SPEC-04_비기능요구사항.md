# SPEC-04 — 비기능 요구사항

| | |
|---|---|
| 버전 | v1.0 |
| 최종 수정 | 2026-08-06 |
| 상위 문서 | [SPEC-00 개발원칙](./SPEC-00_개발원칙.md) |
| 해소 | [G-16](../prd/GAPS.md#g-16) |

PRD 12장은 요구 수준만 한 줄씩 적었다 — "LCP 2.5s 이하", "WCAG AA".
**측정 방법과 합격선이 없으면 통과·실패를 판정할 수 없다.** 이 문서가 그 자리를 채운다.

ID는 `NFR-<분류>-nn`. 각 항목은 **기준 · 측정 · 실패 시 조치** 셋을 갖는다.
셋 중 하나라도 못 적으면 그건 요구사항이 아니라 희망이다.

---

## 1. 성능 (`NFR-P`)

측정 기준은 **모바일 · 4G Slow · p75**다. PRD 12장이 모바일 트래픽 80%를 가정한다.

| ID | 기준 | 측정 | 실패 시 |
|---|---|---|---|
| `NFR-P-01` | **LCP ≤ 2.5s** | Lighthouse CI (모바일 프리셋) + CrUX 필드 p75 | 배포 차단 |
| `NFR-P-02` | **INP ≤ 200ms** | 같음 | 배포 차단 |
| `NFR-P-03` | **CLS ≤ 0.1** | 같음 | 배포 차단 |
| `NFR-P-04` | 초기 JS ≤ **150KB** (gzip) | `next build` 번들 리포트 | 경고 → 리뷰 |
| `NFR-P-05` | 상세·카테고리 페이지 **TTFB ≤ 200ms** | SSG라 정적 응답이어야 한다 | 렌더링 전략 위반 조사 |
| `NFR-P-06` | 이미지는 **WebP/AVIF** + `loading="lazy"` (히어로 제외) | 빌드 검사 | 배포 차단 |
| `NFR-P-07` | 카드 이미지 실제 전송폭 ≤ **480px** | 반응형 `sizes` 설정 | 경고 |

### 1.1 페이지별 예산

| 경로 | LCP 목표 | 근거 |
|---|---|---|
| `/cocktails/{slug}` · 카테고리 | **≤ 2.0s** | SSG + ISR이라 더 엄격하게 잡는다 |
| `/` 탐색 | ≤ 2.5s | 필터가 클라이언트에서 돈다 |
| `/admin/*` | 예산 없음 | 내부 도구 |

**SSG 경로가 2.0s를 못 지키면 렌더링 전략이 어긋난 것이다.** 정적 HTML이 그보다 느릴 이유가 없다.

## 2. 접근성 (`NFR-A`)

목표는 **WCAG 2.2 Level AA**.

### 2.1 명도 대비 — 실측값

Modernist 토큰을 `--color-bg`(#f3f2f2) 위에서 실측한 값이다.
**추정이 아니라 계산 결과이며, 이 표가 사용 가능 여부의 근거다.**

| 토큰 | 대비 | 본문(4.5:1) | 큰 글자·UI(3:1) |
|---|---|---|---|
| `--color-text` #201e1d | **14.86:1** | ✅ | ✅ |
| `--color-accent-700` #ae1800 | **6.41:1** | ✅ | ✅ |
| `--color-neutral-700` #605d5d | **5.83:1** | ✅ | ✅ |
| `--color-accent-600` #dd2b0f | 4.25:1 | ❌ | ✅ |
| `--color-neutral-600` #7d7979 | 3.85:1 | ❌ | ✅ |
| **`--color-accent` #ec3013** | **3.76:1** | ❌ | ✅ |
| `--color-neutral-500` #9b9797 | 2.59:1 | ❌ | ❌ |

`--color-accent-700` on `--color-surface`(#eae9e9) = **5.91:1** — 카드 안에서도 안전하다.

### 2.2 이 표에서 나오는 규칙

| ID | 기준 | 측정 | 실패 시 |
|---|---|---|---|
| `NFR-A-01` | **본문 텍스트는 4.5:1 이상.** accent를 본문에 쓰지 않는다 — `--color-accent-700`을 쓴다 | axe-core CI + §2.1 표 | 배포 차단 |
| `NFR-A-02` | 큰 글자(24px+ 또는 18.66px+ bold)와 UI 컴포넌트는 3:1 이상 | 같음 | 배포 차단 |
| `NFR-A-03` | **`--color-neutral-500`을 텍스트에 쓰지 않는다** (2.59:1) | 코드 검사 | 배포 차단 |
| `NFR-A-04` | 모든 인터랙션이 키보드로 도달·조작 가능 | 수동 체크리스트 | 배포 차단 |
| `NFR-A-05` | `:focus-visible` 2px accent 아웃라인. 기본 링을 제거만 하지 않는다 | axe-core | 배포 차단 |
| `NFR-A-06` | 비활성 필터 칩은 `disabled` + **개수를 함께 읽어준다** | 수동 | 경고 |
| `NFR-A-07` | 차트는 `role="img"` + `aria-label`, **수치를 표로도 제공** | 수동 | 배포 차단 |
| `NFR-A-08` | 색만으로 정보를 전달하지 않는다 | 수동 | 배포 차단 |
| `NFR-A-09` | `prefers-reduced-motion` 존중 | 수동 | 경고 |

### 2.3 발견된 위반 (2026-08-06 · 수정 완료)

이 문서를 쓰면서 실측한 결과 **현재 코드에 AA 미달이 있었다.**

| 위반 | 어디 | 조치 |
|---|---|---|
| `--color-neutral-600`(3.85:1)을 **9~11px 텍스트**에 사용 | `app.css` 6곳 + `.tsx` 3곳 | `--color-neutral-700`(5.83:1)로 교체 |
| `--color-accent`(3.76:1)를 **10~13px 텍스트**에 사용 | `app.css` 5곳 + h6 kicker 4곳 | `--color-accent-700`(6.41:1)로 교체 |

ADR-0001이 "본문 크기 텍스트에 accent를 쓸 때는 `--color-accent-700`을 써야 한다"고
각주로 적어뒀지만 **코드가 따르지 않고 있었다.** 각주는 강제되지 않는다는 증거다 —
그래서 이 문서가 `NFR-A-01`을 배포 차단 조건으로 올린다.

### 2.4 남은 결정 — `.btn-primary`

`.btn-primary`는 accent 배경 위에 `--color-bg` 글자로, 대비가 **3.76:1**이다.
14px/800 레이블은 WCAG의 "큰 글자"(18.66px+ bold)에 미치지 못해 **본문 기준 4.5:1이 적용되고, 미달이다.**

`styles.css`는 시안 정본이라 [ADR-0001](../decisions/ADR-0001-design-system.md)에 따라
임의로 고치지 않는다. 선택지는 셋이고 **제품 결정이다.**

| 안 | 내용 | 비용 |
|---|---|---|
| 가 | 배경을 `--color-accent-700`로 (6.41:1) | 시안의 선명한 빨강이 어두워진다 |
| 나 | 레이블을 18.66px+ bold로 키워 "큰 글자" 기준(3:1) 충족 | 버튼이 커진다 |
| 다 | 현행 유지 + 예외로 문서화 | AA 미달을 안고 간다 |

미결로 두고 [G-16](../prd/GAPS.md#g-16)에 남긴다.

## 3. SEO (`NFR-S`)

유기 검색 유입 50%가 목표다 (PRD 2.2). 이 절은 그 숫자의 전제 조건이다.

| ID | 기준 | 측정 | 실패 시 |
|---|---|---|---|
| `NFR-S-01` | 칵테일·바 상세, 카테고리는 **SSG + ISR** | 빌드 리포트 | 배포 차단 |
| `NFR-S-02` | 필터 결과는 `noindex`. **카테고리 경로는 색인** | 빌드 검사 | 배포 차단 |
| `NFR-S-03` | **축 조합 경로가 0개** | 사이트맵 검사 | 배포 차단 |
| `NFR-S-04` | 발행분 전체가 사이트맵에 포함 | 발행 시 재생성 | 경고 |
| `NFR-S-05` | 칵테일 상세에 Schema.org `Recipe` | 리치 결과 테스트 | 경고 |
| `NFR-S-06` | 모든 공개 페이지에 OG 태그. **카카오톡 카드 미리보기 확인** | 수동 | 발행 전 확인 |
| `NFR-S-07` | 카테고리 페이지마다 **고유 소개 문구** | 어드민 입력 | **경고** (§3.1) |
| `NFR-S-08` | **콘텐츠 앞에 인터스티셜을 두지 않는다** | 수동 | 배포 차단 |

`NFR-S-08`이 [ADR-0004](../decisions/ADR-0004-age-gate.md)를 요구사항으로 굳힌 것이다.
법률 검토가 성인 인증을 요구하면 **이 항목과 정면 충돌하며, 그때는 목표 수치를 함께 조정해야 한다.**

### 3.1 `NFR-S-07`을 경고로 내린 이유 (2026-08-07 개정)

이전 판은 **"발행 차단"** 이었다. 그런데 근거인 `FR-COCKTAIL-031`은 **P1**이다 —
**P1 기능이 P0 발행을 막는 구조**였다 ([G-20](../prd/GAPS.md#g-20)).

Phase 1a의 목표는 [SPEC-01 §8.1](./SPEC-01_시스템개요_범위.md)이 정한 **칵테일 100종 발행**이지 카테고리 문구가 아니다.
문구가 없다고 100종이 못 나가면 우선순위가 뒤집힌다.

→ **경고로 내린다.** 저장 구조([SPEC-06 §3.8](./SPEC-06_데이터모델_ERD.md) `category_intro`)는 1a에 만들고,
`FR-COCKTAIL-031` 착수(P1) 시점에 **차단으로 올린다.**

색인 가치에 대한 지적은 유효하다 — 목록만 있는 페이지는 약하다. 다만 그건 **1a에서 검증할 것**(유기 검색 유입)의 결과로 판단한다.

| ID | 기준 | 실패 시 |
|---|---|---|
| `NFR-L-01` | 과음 경고가 **모든 페이지** 하단에 있다 | 배포 차단 |

| `NFR-L-05` | 주류 광고 규제 **자문 완료** | **유료 브랜드 노출 시작 차단** |

### 8.1 `NFR-L-05`를 트리거 기반으로 나눈 이유 (2026-08-07 개정)

이전 판은 **"법률 검토 1회 완료 → 정식 오픈 차단"** 하나였다.
[SPEC-08 §8](./SPEC-08_보안_권한_개인정보.md)의 검토 항목 3건을 뜯어보니 **성격이 달랐다.**

| 항목 | 성격 | 언제 |
|---|---|---|
| ① 전면 성인 인증이 실제로 요구되는가 | 변호사 자문 | 접점이 약하다 — [ADR-0004](../decisions/ADR-0004-age-gate.md)대로 **판매를 안 한다** |
| ② 브랜디드 콘텐츠 주류광고 기준 | 변호사 자문 | **유료 브랜드 노출을 시작할 때.** 그전엔 접점 0 |
| ③ `audit_log` 파기 예외 적법성 | **문서 작성** | **실사용자 수집 전.** 처방침 문안의 일이다 |

③은 소셜 로그인(`FR-USER-001`)이 붙는 순간 **개인정보 처리방침이 법정 의무**가 되는 것과 한 덩어리다.
수집 항목이 적고([SPEC-08 §5.1](./SPEC-08_보안_권한_개인정보.md)이 생년월일·전화번호·주소·결제를 이미 배제),
SPEC-08 §5.3 자신이 **"이 예외는 개인정보 처리방침에 명시한다"** 고 적어 뒀다.

→ **①②를 `NFR-L-05`(트리거: 유료 브랜드 노출)로, ③을 `NFR-L-04`(트리거: 실사용자 수집)로 나눈다.**

**Phase 1a의 규제 접점은 0이다** — `article`(Phase 2)·PARTNER(1b)가 없고,
`ingredient_brand.is_sponsored`는 프로토타입에 브랜드 데이터가 없어 시드가 0건이다.
이슈 008·023이 "1a에서 켜지 않는다"를 DoD로 고정했다.

> ⚠️ **이 판단은 구조적 읽기이지 법률 판단이 아니다.** ADR-0004가 스스로 밝힌 것과 같은 한계다.
> 유료 제휴를 시작할 때는 계약서도 필요하므로 그 시점에 함께 본다.
