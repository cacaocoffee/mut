## 근거

**`FR-ADMIN-003`**: 발행 게이트 실패 시 실패한 항목을 **전부 한 번에** 보여준다. **하나씩 고치게 하지 않는다**
**`NFR-O-01`**: 에디터가 개발자 없이 발행 — **신규 1건을 어드민만으로 완료** (인수 시나리오)
**`FR-ADMIN-002`**: 발행 워크플로는 `draft → published → archived`이며 **되돌릴 수 있다**

**입력 강제** — 서버가 정본이고 UI는 보조다 (`PRIN-T05`)

| FR | 요구 |
|---|---|
| `FR-COCKTAIL-002` | `style_primary`는 `styles`에 포함된 값 중에서만. **UI가 `styles` 선택 결과로 후보를 좁힌다** |
| `FR-COCKTAIL-008` | 향·맛 태그 1~3개. **4개째는 UI가 막는다** |
| `FR-COCKTAIL-014` | `slug`는 최초 발행 이후 변경 불가. **어드민에서 입력란을 비활성화한다** |

**`PRIN-T05`**: **프론트 검증은 UX용 중복이다. 없어도 데이터가 깨지지 않아야 한다**

**SPEC-07 §1.4**: `violations`는 항상 배열이고 실패한 항목을 **전부** 담는다. `code`는 `INV-`/`GATE-` ID를 그대로 쓴다 — **클라이언트가 문구가 아니라 코드로 분기**

**SCREENS-06 어드민** (G-15 해소) — **발행 조건 패널 · 입력 강제**가 화면 정본

## RED

### 발행 조건 패널 (`FR-ADMIN-003`, SCREENS-06 — 요체)

1. **`게이트_실패_항목이_전부_한_번에_보인다`** — 하나씩 고치게 하지 않는다
2. `실패_항목마다_어느_필드인지_표시된다` — `violations[].field`
3. `실패_항목마다_이유가_표시된다` — `violations[].message`
4. `GATE_ID가_표시되거나_매핑된다` — 코드로 분기 (SPEC-07 §1.4)
5. `게이트_통과_상태가_실시간으로_보인다` — 저장 전에도
6. `전부_통과하면_발행_버튼이_활성화된다`
7. `발행_버튼을_눌러도_서버가_다시_검사한다` (`PRIN-T05` — UI는 보조)

## GREEN

### 발행 조건 패널 (RED 1~7 — SCREENS-06 정본)

```tsx
// FR-ADMIN-003 — 실패 항목을 전부 한 번에. 잘라내지 않는다
{violations.map(v => <GateFailure key={v.code} {...v} />)}
```

서버가 `violations` 배열을 통째로 준다 (이슈 003·013·025). **프론트는 전부 렌더할 뿐이다.**

RED 5(실시간 상태)는 저장 전 로컬 판정이다 — **서버 게이트를 복제하지 않는다.** 필수 필드가 비었는지 정도만 보고, 최종 판정은 발행 요청의 응답이다 (RED 7).

### 입력 강제는 UX (RED 15)

`style_primary` 후보 좁히기·향맛 4개째 차단은 **편의**다. 서버가 정본이고 RED 15가 그것을 확인한다.

### 재료 선택 (RED 22 — `PRIN-D01`)

**프리텍스트 입력란을 만들지 않는다.** 있으면 언젠가 쓰이고, 그 순간 역검색과 바 연결이 무너진다.
