# 경계 위반 픽스처 (ISSUE-001)

**이 패키지는 일부러 규칙을 어긴다.** 프로덕션 코드가 아니다.

`ModuleBoundaryTest` 는 같은 규칙을 두 번 돌린다.

| 대상 | 기대 |
|---|---|
| `kr.mut.**` (main 산출물) | 위반 **0건** |
| `kr.mut.architecture.fixture.**` (여기) | 위반 **1건 이상** |

두 번째가 없으면 "통과하는 경계 테스트"가 실은 **아무것도 안 하는 테스트**일 수 있다.
규칙 패턴이 오타 났거나, 임포트 범위가 비었거나, 조건이 항상 참이어도 초록이 뜨기 때문이다.

패키지 구조를 `<module>/<layer>` 로 흉내 내 둔 이유도 그것이다 —
규칙은 `..cocktail.repository..` 같은 `..` 패턴이라 루트가 어디든 똑같이 걸린다.

## 손댈 때

규칙을 추가하면 **그 규칙을 어기는 픽스처도 함께** 넣는다.
픽스처 없이 규칙만 늘리면 `ModuleBoundaryTest` 의 "잡는지" 단언이 비어 통과해 버린다.
